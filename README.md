# mfcapture

## 概要

本プログラムは、Web カメラ、動画ファイル、静止画像から取得した画像を OpenGL
テクスチャへ転送し、GLSL で変形して表示する C++ アプリケーションです。
画像処理プログラミングの勉強会で、CPU と GPU による画像処理の違いや、
カメラの内部パラメータを用いたレンズ歪み補正を学ぶサンプルとして使用します。

Windows のカメラ入力には Microsoft Media Foundation（MSMF）を直接使用します。
その他のプラットフォームのカメラ入力と動画入力には OpenCV を使用し、描画と UI
には OpenGL、GLFW、Dear ImGui を使用します。

カメラ較正や ChArUco Board の作成は本プログラムでは行いません。
`calib-wom-msmf` で作成した較正ファイルを読み込み、その結果を表示処理に利用します。

## 主な機能

- Web カメラ、動画ファイル、静止画像からの入力
- Windows Media Foundation による H.264／MJPG の取得、デコード、RGB 変換
- 解像度、フレームレート、コーデックの組み合わせ選択
- 全フレーム処理とレイテンシ優先処理の切り替え
- GLSL による入力画像の投影変換
- JSON 形式のカメラ内部パラメータの読み込み
- 「なし」「OpenCV」「OpenGL」から選択できるレンズ歪み補正
- JSON 構成ファイルによる表示設定とシェーダー設定の管理

## プログラムの処理の流れ

`mfcapture.cpp` のメインループでは、一フレームを次の順序で処理します。

1. `Menu` が UI を描画し、入力、投影方式、歪み補正方法を更新する。
2. `Capture` が現在の入力源からフレームを取得する。
3. OpenCV 補正を選択している場合は、CPU 上の `cv::Mat` に取得して
   `Undistortion::apply()` で補正する。
4. 補正済み、または未補正のフレームを OpenGL テクスチャへ転送する。
5. `Menu::setup()` が通常表示用または OpenGL 歪み補正用シェーダーを設定する。
6. `Framebuffer` が GLSL による変換結果を生成する。
7. 最終画像と Dear ImGui の UI を画面へ描画する。

OpenCV 補正は、キャプチャ直後かつ GPU への転送前に行います。この位置なら
GPU へ転送した画像を CPU へ読み戻す必要がなく、補正結果だけを一度アップロード
できます。OpenGL 補正では CPU 上の補正処理を行わず、フラグメントシェーダーが
入力テクスチャの参照座標を変換します。

`framebuffer.resize(frame)` は描画ループ内で呼び出しますが、入力フレームの大きさが
前回と同じ場合は再確保を行いません。入力源や解像度が変化したフレームだけ
Framebuffer Object を作り直すため、通常フレームで大きなオーバーヘッドには
なりません。

## レンズ歪み補正

### 較正ファイル

「ファイル」メニューの「較正ファイルを開く」から、Native File Dialog Extended
によるダイアログで JSON ファイルを選択します。ファイルには次の行列が必要です。

- `camera matrix`: 3 行 3 列のカメラ行列
- `distortion`: 5 行 1 列の歪み係数

読み込みは一時変数へ行い、両方の行列を正常に取得できた場合だけ現在のパラメータを
置き換えます。失敗した場合は補正を「なし」に戻し、不完全な値を使用しません。

### OpenCV 方式

`cv::initUndistortRectifyMap()` で補正座標マップを作成し、
`cv::remap()` でフレームを補正します。座標マップは画像サイズが変わったときだけ
再作成し、毎フレームの不要な計算を避けます。

### OpenGL 方式

`undistortion.vert` と `undistortion.frag` を使用します。フラグメントシェーダーで
カメラ行列と歪み係数から入力画像の参照座標を求めるため、CPU 側で補正画像を
作成しません。既定の `orthographic.vert`、`normal.frag` とは UI のラジオボタンで
切り替えられます。

## 主要クラスと責務

### `Camera` と入力実装

`Camera` はキャプチャスレッド、共有フレーム、排他制御、レイテンシ優先フラグを
管理する基底クラスです。

- `CamMf`: Windows Media Foundation によるカメラ入力
- `CamCv`: OpenCV によるカメラ、動画、ネットワーク入力
- `CamImage`: 静止画像入力
- `Capture`: 入力実装の所有、切り替え、開始・停止、フレーム転送の窓口

### `Config`、`Preference`、`Intrinsics`

- `Config`: JSON 構成ファイルの読み込みと表示設定の管理
- `Preference`: 投影方式ごとの説明、通常シェーダー、補正シェーダーの保持
- `Intrinsics`: 画角、中心位置、解像度、フレームレートの保持

### `Undistortion`

較正ファイルのカメラ行列と歪み係数を保持します。OpenCV 方式では補正マップを
キャッシュして `cv::remap()` を実行し、OpenGL 方式では GLSL の uniform に渡す
焦点距離、主点、歪み係数を提供します。

### `Menu`

Dear ImGui による入力選択、表示設定、較正ファイル読み込み、補正方式選択、
エラー表示を担当します。ファイル選択には Native File Dialog Extended を使用します。

## 構成ファイル

既定の構成ファイルは `mfcapture_config.json` です。主な項目は次のとおりです。

- ウィンドウサイズと背景色
- 展開メッシュのサンプル数
- カメラ姿勢、焦点距離、焦点距離範囲
- 初期表示画像
- 投影方式ごとの説明、画角、中心、解像度、fps
- `shader`: 通常表示用の頂点・フラグメントシェーダー
- `undistortion`: OpenGL 歪み補正用の頂点・フラグメントシェーダー

起動時に両方のシェーダーを構築し、UI で選択された補正方式に応じて使用します。

## 基本操作

1. 「ファイル」メニューから画像、動画、または較正ファイルを開く。
2. カメラを使用する場合は「入力」パネルで装置を選択する。
3. Windows では解像度、フレームレート、符号化方式を選択する。
4. 必要に応じて「レイテンシ優先」を選択する。
5. 「開始」を押してキャプチャを開始する。
6. 「歪み補正」で「なし」「OpenCV」「OpenGL」のいずれかを選択する。

較正ファイルを読み込むまでは OpenCV と OpenGL の補正を選択できません。

## 開発環境とビルド

- C++17
- CMake 3.13 以降
- Visual Studio 2022 以降（Windows、x64）
- OpenCV 4.13.0
- GLFW 3.4
- Dear ImGui 1.92.8
- Native File Dialog Extended 1.3.0

Windows での基本的なビルド例：

```powershell
cmake -S . -B build
cmake --build build --config Debug
cmake --build build --config Release
```

初回の CMake 構成時には、必要な依存ライブラリを `libs` 以下へ取得します。
`libs` はジャンクションではなく、プロジェクト固有の依存ファイル置き場です。
ビルド後は、シェーダー、構成ファイル、画像、フォント、OpenCV DLL が実行ファイルの
ディレクトリへコピーされます。

## 開発時の確認事項

- OpenCV 補正は GPU 転送前、OpenGL 補正は GLSL 内だけで実行すること。
- 補正マップと Framebuffer Object は、入力サイズが変化した場合だけ再作成すること。
- 較正ファイルの読み込みに失敗した場合、以前の値を部分的に更新しないこと。
- 通常シェーダーと補正シェーダーは同じ投影設定から選択できること。
- Windows 固有処理は `CamMf` と `Capture` に閉じ込めること。
- コメントと Doxygen を実装変更と同時に更新すること。
