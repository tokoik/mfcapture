2. カメラモデリングの基礎原理

Theory
ピンホールモデルと透視投影

3次元世界座標系 $(X_w, Y_w, Z_w)$ から2次元画像平面 $(u, v)$ への透視投影 (Perspective Projection) 方程式：

$$s \begin{bmatrix} u \\ v \\ 1 \end{bmatrix} = K \begin{bmatrix} R & t \end{bmatrix} \begin{bmatrix} X_w \\ Y_w \\ Z_w \\ 1 \end{bmatrix}$$
カメラ内部行列 (Camera Matrix $K$): $$K = \begin{bmatrix} f_x & 0 & c_x \\ 0 & f_y & c_y \\ 0 & 0 & 1 \end{bmatrix}$$ $f_x, f_y$: 画素単位の焦点距離、$c_x, c_y$: 主点（光学中心）
カメラ外部行列 (Extrinsic Parameters $[R | t]$)

世界座標系からカメラ座標系への剛体変換 $P_c = R P_w + t$ を表します。

回転行列 (Rotation Matrix $R$):
3×3 の直交行列。カメラの向き（回転）を表します。
並進ベクトル (Translation Vector $t$):
3×1 の位置ベクトル。世界座標系原点に対するカメラの 3D 位置オフセットを表します。
※ 内部行列 $K$ はカメラ固有ですが、外部パラメータ $[R | t]$ は撮影フレーム（ボード位置）ごとに変化します。

3. レンズ歪みの数理モデル

Mathematics
1. 放射歪み (Radial Distortion)

レンズの屈折形状に起因する樽型・糸巻き型歪み。

$$x_{\text{distorted}} = x(1 + k_1 r^2 + k_2 r^4 + k_3 r^6)$$ $$y_{\text{distorted}} = y(1 + k_1 r^2 + k_2 r^4 + k_3 r^6)$$ ※ $r^2 = x^2 + y^2$ (正規化座標上の距離)
2. 接線歪み (Tangential Distortion)

レンズとイメージセンサーの傾き・非平行に起因する歪み。

$$\delta x = 2 p_1 x y + p_2(r^2 + 2x^2)$$ $$\delta y = p_1(r^2 + 2y^2) + 2 p_2 x y$$ 本システムでは $[k_1, k_2, p_1, p_2, k_3]$ の5係数を使用

4. ChArUco Board によるキャリブレーション

Calibration
キャリブレーション方式 特徴 課題
チェスボード (Chessboard) サブピクセル精度の超高精度な交点検出 一部でも隠れるとパターン全体が検出不能
ArUco マーカー 個別IDによりオクルージョン（遮蔽）に非常に強い コーナー検出精度がチェスボードよりやや低い
ChArUco Board (両者の融合) ArUcoで個別交点を特定し、チェスボード交点で超高精度検出！ マーカー検出＋ボード認識の処理ステップ

4.1 キャリブレーションで推定するもの

Estimation
最適化フロー
flowchart TD A["既知の3D点 (X,Y,0)"] --> C["投影モデル K, d, R, t"] B["検出2D点 (u,v)"] --> D["再投影誤差 (Reprojection Error)"] C --> D D -->|"全標本でLM法最小化"| E["カメラ行列 K & 歪み係数 d"]
推定対象パラメータ
  • 全画像で共通 (内部): カメラ行列 $K$ ($f_x, f_y, c_x, c_y$)、歪み係数 $d$ ($k_1..k_3, p_1..p_2$)
  • 画像ごとに異なる (外部): ボード姿勢 $R_i, t_i$
  • 観測値 (2D): 画像から検出した ChArUco 交点画素座標 $(u, v)$
  • 既知量 (3D): ボード設計寸法に基づく 3D 交点座標 $(X, Y, 0)$

4.2 C++ 実装：ChArUco Board の定義と構成

C++ Code 
cv::aruco::Dictionary dictionary =
  cv::aruco::getPredefinedDictionary(cv::aruco::DICT_6X6_250);

// CharucoBoard コンストラクタ呼び出し
cv::aruco::CharucoBoard board{
  cv::Size{10, 7},   // squaresX, squaresY
  0.030f,            // squareLength [m]
  0.022f,            // markerLength [m]
  dictionary         // ArUco 辞書
};

cv::aruco::CharucoDetector detector{board};
ChArUco Board とは

チェスボードの「高精度交点検出」と ArUco マーカーの「個体識別・遮蔽耐性」を組み合わせたハイブリッドパターンです（OpenCV チュートリアル準拠）。 黒マス内に固有 ID マーカーが交互配置され、ボードの一部が画面外や物体の陰に隠れていても交点座標と位置関係を正確に決定できます。

`cv::aruco::CharucoBoard` 引数解説:
・size (`cv::Size`): 横・縦のマス数 (10, 7)
・squareLength (`float`): マスの物理長 [m] (例: 0.030f = 3cm)
・markerLength (`float`): マーカーの物理長 [m] (`markerLength < squareLength`)
・dictionary: マーカー生成・識別用辞書パターン

4.3 C++ 実装：検出と標本座標マッチング

C++ Code 
std::vector<cv::Point2f> charucoCorners;
std::vector<int> charucoIds;

// 1. ボード交点検出
detector.detectBoard(frame, charucoCorners, charucoIds);

if (charucoCorners.size() >= 4) {
  std::vector<cv::Point3f> objectPoints;
  std::vector<cv::Point2f> imagePoints;

  // 2. 3D-2D 対応点の抽出
  board.matchImagePoints(
    charucoCorners, charucoIds,
    objectPoints, imagePoints);

  allObjectPoints.push_back(std::move(objectPoints));
  allImagePoints.push_back(std::move(imagePoints));
}
処理概略と `corners.size() >= 4` の理由

なぜ 4 点以上が必要か：
平面オブジェクトの 3D 姿態・透視投影変換 (PnP 問題 / ホモグラフィ) を幾何学的に決定するには、最低 4 点の対応点が必要となるためです。交点が 4 点未満の場合は幾何学的拘束条件が成り立たないため処理をスキップします。

`detectBoard(image, corners, ids)`:
・`image`: 入力画像 (`cv::Mat`)
・`corners`: 検出された交点の 2D 画素座標（出力）
・`ids`: 検出交点に対応する固有 ID 配列（出力）
`matchImagePoints(cCorners, cIds, objPts, imgPts)`:
・`cCorners` / `cIds`: 検出交点座標および ID 配列（入力）
・`objPts`: ID に対応する理論 3D ボード座標 $(X, Y, 0)$（出力）
・`imgPts`: `objPts` と 1 対 1 対応する観測 2D 画素座標（出力）

4.4 C++ 実装：最適化計算 (`calibrateCamera`)

C++ Code 
cv::Mat K, distortion;
std::vector<cv::Mat> rvecs, tvecs;

double rms = cv::calibrateCamera(
  allObjectPoints,  // 全標本の 3D 点群
  allImagePoints,   // 全標本の 2D 画素点群
  imageSize,        // 画像サイズ
  K,                // カメラ内部行列 (出力)
  distortion,       // 歪み係数 (出力)
  rvecs, tvecs,     // 各標本の姿勢 [R|t] (出力)
  cv::noArray(), cv::noArray(), cv::noArray(),
  0                 // 較正オプションフラグ
);
「最適化計算」の意味と `calibrateCamera`

最適化計算 (Optimization) とは：
実測された 2D 画素座標 $p$ と、推定パラメータ $(K, d, R_i, t_i)$ で 3D 点を画像上に再投影した座標 $\hat{p}$ との差（**再投影誤差 Reprojection Error**）の自乗和を最小化する非線形最小二乗問題です。**Levenberg-Marquardt (LM) 法**により内部行列 $K$、歪み係数 $d$、各標本のカメラ姿勢 $[R_i | t_i]$ を反復計算で同時に最適推定します。

`calibrateCamera()` 主要引数:
・`objectPoints` / `imagePoints`: 全標本分（複数フレーム）の 3D ボード座標点群および 2D 観測画素点群
・`imageSize`: 入力画像の解像度 (`cv::Size`)
・`cameraMatrix` ($K$) / `distCoeffs` ($d$): 最適化された内部行列および 5 歪み係数 (出力)
・`rvecs` / `tvecs`: 標本ごとの回転ベクトル $r_i$ および並進ベクトル $t_i$ (出力)

データ項目の解説
  • `camera matrix`: $3 \times 3$ のカメラ行列 $K$。$[f_x, 0, c_x; 0, f_y, c_y; 0, 0, 1]$

  • `mfcapture` は一時検証後に安全にこのパラメータを読み込み適用

9. 歪み補正パイプラインの比較 (CPU vs GPU)

Comparison
評価項目 OpenCV 歪み補正 (CPU) OpenGL 歪み補正 (GPU / GLSL)
実行エンジン CPU (`cv::remap`) GPU (`undistortion.frag`)
パイプライン位置 キャプチャ直後、OpenGL 転送前に実行 OpenGL テクスチャ描画時にシェーダーで実行
CPU 負荷 解像度に比例して高い ほぼゼロ

10. OpenCV (CPU) による C++ 歪み補正処理

CPU Pipeline 
// 1. 初期化・マップ作成（解像度変更時のみ1回実行）
cv::Mat map1, map2;
cv::initUndistortRectifyMap(
    cameraMatrix, distCoeffs,
    cv::Mat(),       // 補正回転 R (単位行列)
    cameraMatrix,    // 新しいカメラ行列 New K
    imageSize,       // 画像サイズ
    CV_32FC1,        // マップの型
    map1, map2       // 出力参照座標マップ
);

// 2. 毎フレームの補正実行 (CPU)
cv::Mat srcFrame, dstFrame;
cv::remap(
    srcFrame, dstFrame,
    map1, map2,
    cv::INTER_LINEAR  // 双線形補間
);
C++ CPU 補正のポイントと引数
`cv::initUndistortRectifyMap()`:
補正後画像の各ピクセルが撮影画像のどこを参照すべきかの座標ルックアップテーブル (`map1`, `map2`) を事前生成します。重い計算のため毎フレーム呼ばず**解像度変更時のみ呼び出す最適化**を行います。
`cv::remap()`:
事前計算された `map1`, `map2` を用いて、`srcFrame` からピクセル値を取り出し `dstFrame` へ再配置します。`INTER_LINEAR` (双線形補間) により滑らかな画質が得られます。

11. GLSL 歪み補正シェーダー (`undistortion.frag`)

GLSL Code 
// 理想的な正規化座標 p = (x, y) の算出
vec2 p = (v_texcoord * size - center) / focal;

// 放射歪み & 接線歪みモデル適用
float r2 = dot(p, p);
float radial = 1.0 + dist_k.x * r2 + dist_k.y * r2 * r2 + dist_k3 * r2 * r2 * r2;
vec2 tangential = vec2(
    2.0 * dist_k.z * p.x * p.y + dist_k.w * (r2 + 2.0 * p.x * p.x),
    dist_k.z * (r2 + 2.0 * p.y * p.y) + 2.0 * dist_k.w * p.x * p.y
);
vec2 pd = p * radial + tangential;

// 歪んだ位置の UV 座標でテクスチャ参照
vec2 uv = (pd * focal + center) / size;
fragment = texture(image, uv);

12.1 なぜ「逆向き」に座標を求めるのか

Backward Mapping
逆写像 (Backward Mapping) の流れ
flowchart TD O["補正後出力画素 (u, v)"] --> N["K⁻¹ 正規化座標 (x, y)"] N --> M["歪みモデル (xd, yd)"] M --> P["K 入力画素 (ud, vd)"] P --> S["入力画像をサンプル"] S --> O2["出力色"]
逆写像のメリット

入力画素を補正後へ移動する順写像では、丸め誤差により穴やピクセルの衝突が発生します。

逆写像ならすべての出力ピクセルについて参照元が一意に決まり、cv::remap() と GLSL texture() の両方で破綻なく処理できます。

12.2 座標系を混同しない注意点

Coordinates
単位と範囲の整理
  • $f_x, f_y, c_x, c_y$ は ピクセル単位
  • GLSL テクスチャ UV は 0.0 〜 1.0
  • OpenCV 原点は左上。OpenGL との上下反転に注意。
  • 解像度変更時は焦点距離・主点も等倍スケール。
変換フロー
補正後UV [0,1] ─×(W,H)→ 補正後画素 [px]
  ─(画素−主点)/焦点→ 正規化カメラ座標
  ─歪み式→ 歪んだ正規化座標
  ─×焦点＋主点→ 入力画素 [px]
  ─/(W,H)→ 入力UV [0,1] ─texture→ 色
