1. CamMf の概要と設計目標

CamMf.md Section 1
🎯 モジュールの役割
  • Media Foundation 固有型の完全隠蔽
    UI や描画ループに Media Foundation 固有オブジェクトを露出させず、抽象化された Camera インターフェースを提供。
  • 柔軟なデコードとフォーマット変換
    カメラ出力 (MJPG/H.264/NV12/YUY2) を MFT 経由で最適に処理し、描画用の RGB32 (RGBA) へ変換。
  • CPU メモリ & GPU PBO 転送
    キャプチャしたフレームを CPU メモリ上へ転送し、OpenGL PBO 経由で高速描画。
⚙️ 4つの設計の柱
  • 遅延初期化 (Delayed Initialization)
    デバイス/フォーマット列挙時には重いデコーダを初期化せず、起動を高速化。
  • Low Latency 最適化
    MF_LOW_LATENCY & CODECAPI_AVLowLatencyMode を適用しディレイを極小化。
  • ストリーム変化の自動追従
    解像度やフォーマット変更時の MF_E_TRANSFORM_STREAM_CHANGE を自動回復。
  • スレッドセーフ制御
    バックグラウンド取得スレッドとメイン描画スレッドを std::mutex と try_to_lock で非同期同期。

4. COM & Media Foundation 初期化

ComInitializer::initialize
📝 初期化シーケンス
  • CoInitializeEx(nullptr, COINIT_MULTITHREADED) で COM ライブラリをマルチスレッドモードで起動。
  • MFStartup(MF_VERSION, MFSTARTUP_FULL) で Media Foundation 基盤を全機能有効で初期化。
  • MFCreateAttributes で検索用属性ストアを作成。
  • MF_DEVSOURCE_ATTRIBUTE_SOURCE_TYPE_VIDCAP_GUID を指定し、MFEnumDeviceSources で接続中のカメラを全検出。
💻 ソースコード
const char* CamMf::ComInitializer::initialize() {
  if (FAILED(CoInitializeEx(nullptr, COINIT_MULTITHREADED)))
    return "Failed to initialize COM library.";
  coInitialized = true;

  if (FAILED(MFStartup(MF_VERSION, MFSTARTUP_FULL)))
    return "Failed to start Media Foundation.";
  mfStarted = true;

  // 属性ストア作成 & デバイス列挙...
  MFEnumDeviceSources(pAttributes, &ppSourceActivate, &cSourceActivate);
}

5. フォーマット列挙と遅延初期化

enumerateFormats()
⚡ 遅延初期化 (Delayed Initialization) の意図

カメラが対応するすべてのフォーマットを調べる際、毎回重い MFT デコーダやコンバータを初期化すると列挙に数秒の遅延が発生します。

enumerateFormats() では IMFSourceReader::GetNativeMediaType を使ってメタデータ（解像度・FPS・GUID）のみを高速読み出し、選択時 (setFormat) に初めてパイプラインを構築します。

🔍 メタデータ取得ロジック
// Native Media Type を一つずつ列挙
while (SUCCEEDED(pSourceReader->GetNativeMediaType(
    MF_SOURCE_READER_FIRST_VIDEO_STREAM, index++, &pMediaType))) {

  pMediaType->GetGUID(MF_MT_SUBTYPE, &subType);
  MFGetAttributeSize(pMediaType, MF_MT_FRAME_SIZE, &w, &h);
  MFGetAttributeRatio(pMediaType, MF_MT_FRAME_RATE, &num, &den);

  // 判定と表示用 CaptureFormat リスト構築
  formatList.push_back({ resStr, fpsStr, codecStr, idx });
}

8. 最適化出力バッファ構築

createDecoderBuffer & createConverterBuffer
📐 NV12 16ピクセルアラインメント計算

NV12 フォーマットはハードウェアデコーダの都合上、幅・高さを 16 の倍数にアラインメント（繰り上げ）する必要があります。 

// 16の倍数へ丸め込み
const auto alignedW{ (width + 15) & ~15 };
const auto alignedH{ (height + 15) & ~15 };

// NV12 の理論計算サイズ = W * H * 1.5
const auto cbCalc{ (alignedW * alignedH * 3) / 2 };
const auto cbDecoder{ std::max(streamInfo.cbSize, cbCalc) };

MFCreateAlignedMemoryBuffer(cbDecoder, alignment, &pDecoderBuffer);
🎨 RGB32 バッファ計算

カラーコンバータ出力（RGB32）には Media Foundation のヘルパー関数 MFCalculateImageSize を用いて正確な必要バイト数を計算します。 

UINT32 cbConverterCalc{ 0 };
MFCalculateImageSize(MFVideoFormat_RGB32, width, height, &cbConverterCalc);

UINT32 cbConverter = std::max(convInfo.cbSize, cbConverterCalc);

MFCreateAlignedMemoryBuffer(cbConverter, alignment, &pConverterBuffer);

9. キャプチャ・デコード・変換ループ

capture() Loop Detail
🔄 capture() スレッドの処理フロー
  • ReadSample で Source Reader から IMFSample を取得。
  • 圧縮フォーマットなら pDecoder->ProcessInput() でデコーダへ投入。
  • pDecoder->ProcessOutput() を呼び出して NV12 フレームを取得。
  • pConverter->ProcessInput() & ProcessOutput() で RGB32 に変換。
  • pBuffer->Lock() でピクセルポインタを取得し、image バッファへ memcpy。
💻 MFT 処理コード例
// 1. デコーダ投入
pDecoder->ProcessInput(0, pSample, 0);

// 2. 出力取得ループ
MFT_OUTPUT_DATA_BUFFER outBuffer{ 0, pDecodedSample, 0, nullptr };
hr = pDecoder->ProcessOutput(0, 1, &outBuffer, &dwStatus);

if (hr == MF_E_TRANSFORM_STREAM_CHANGE) {
  // ストリーム変更に対応 (次スライド)
}

10. 動的ストリーム変更への自動対応

MF_E_TRANSFORM_STREAM_CHANGE
⚠️ ストリーム変更発生時の回復ステップ
STEP 1: NV12 再探索

GetOutputAvailableType をループし、変更後のストリームに対応する NV12 フォーマットを再検出。

STEP 2: 属性の引き継ぎ

入力メディアタイプから解像度・FPS・アスペクト比・インターレースモードを抽出し、新しい出力タイプへコピー設定。

STEP 3: バッファ再構築

createDecoderBuffer() と createConverterBuffer() を再実行し、ProcessOutput をやり直す。

12. フレーム転送と OpenGL PBO 連携

Camera::transmit(GLuint buffer)
🚀 非ブロッキング転送メカニズム
  • std::unique_lock<std::mutex> lock(mtx, std::try_to_lock) を使用。
  • 描画スレッドがミューテックスのロックに失敗した場合は待機せず false を返し、前フレームの表示を維持してフレームドロップを回避。
  • ロック成功かつ captured == true の時、OpenGL GL_PIXEL_PACK_BUFFER へ高速転送。
💻 transmit() 実装
bool Camera::transmit(GLuint buffer) {
  std::unique_lock<std::mutex> lock(mtx, std::try_to_lock);
  if (lock.owns_lock() && captured) {
    const auto length{ std::min(image.size(), expected) };

    glBindBuffer(GL_PIXEL_PACK_BUFFER, buffer);
    glBufferSubData(GL_PIXEL_PACK_BUFFER, 0, length, image.data());
    glBindBuffer(GL_PIXEL_PACK_BUFFER, 0);

    if (!reusableFrame) captured = false;
    return true;
  }
  return false;
}

13. リソース解放と安全な停止

stop() & close()
🛑 安全なシャットダウン手順
  • 1. スレッド停止フラグ: running = false に設定。
  • 2. ブロッキング解除: pSourceReader->Flush() を呼び出し、ReadSample の待機状態を即座に破棄。
  • 3. スレッド合流: thr.join() でキャプチャスレッドの終了を完全同期。
  • 4. MFT 終了通知: ProcessMessage(MFT_MESSAGE_NOTIFY_END_STREAMING) を送信。
🛡 SafeRelease による破棄
template <class T> void SafeRelease(T** ppT) {
  if (*ppT) {
    (*ppT)->Release();
    *ppT = nullptr;
  }
}

void CamMf::close() {
  cleanUpTransform(&pDecoder);
  cleanUpTransform(&pConverter);
  SafeRelease(&pDecoderBuffer);
  SafeRelease(&pConverterBuffer);
  SafeRelease(&pSourceReader);
  SafeRelease(&pMediaSource);
}

15. まとめ

Conclusion
💡 CamMf クラス実装の優位点まとめ
  • 完全な抽象化: 高レベルクラス Camera と CaptureFormat により、UI や描画ループから Media Foundation 固有型を分離。
  • 徹底した低遅延化: MF_LOW_LATENCY、CODECAPI_AVLowLatencyMode、最新フレーム上書きロジックによりリアルタイム画像処理に最適化。
  • 堅牢なエラーハンドリング: 動的ストリーム変更 (MF_E_TRANSFORM_STREAM_CHANGE) への追従と SafeRelease による漏れのないリソース管理。
